# 浏览器原理

## 浏览器架构

### 多进程架构
- **浏览器主进程**：控制界面，地址栏、书签、前进后退，管理其他进程
- **GPU进程**：UI 渲染，界面绘制
- **网络进程**：网络请求，资源加载
- **渲染进程**：每个标签页一个，运行 JS、CSS、HTML，页面渲染
- **插件进程**：每个插件一个进程

好处：一个页面崩溃不影响其他页面，沙箱隔离更安全。

### 从输入 URL 到页面展示全过程

1. **DNS 解析**：域名 → IP 地址
   - 浏览器缓存 → 操作系统缓存 → 路由器缓存 → ISP DNS 缓存 → 根域名服务器迭代查询

2. **TCP 连接**：三次握手建立连接

3. **发送 HTTP 请求**：请求行 + 请求头 + 空行 + 请求体

4. **服务器处理请求**：返回 HTTP 响应

5. **浏览器解析渲染**：
   - 解析 HTML 构建 DOM 树
   - 解析 CSS 构建 CSSOM 树
   - DOM + CSSOM 合并成渲染树（Render Tree）
   - 布局（Layout）计算每个节点位置大小
   - 绘制（Paint）绘制到屏幕

6. **TCP 断开连接**：四次挥手断开连接

## 重排 Reflow vs 重绘 Repaint

### 重排 Reflow（回流）
- 改变元素几何属性（宽高、位置），触发浏览器重新布局
- 影响范围：整个文档重新布局，性能开销大
- 触发场景：
  - DOM 元素增删
  - 位置尺寸改变
  - 内容改变
  - 窗口大小改变
  - 读取 offsetWidth/offsetHeight 等布局属性也会触发（强制同步布局）

### 重绘 Repaint
- 不改变几何位置，只改变外观（颜色、背景色），只重新绘制
- 性能开销比重排小，但仍有开销

**关系**：重排一定会触发重绘，重绘不一定重排。

### 优化减少重排
- 批量修改 DOM，离线修改（display: none 后修改再显示）
- 不要逐条改样式，用 class 一次性改
- 避免多次读取布局属性，把读取放一起，修改放一起
- 绝对定位脱离文档流，改动不影响整体
- 用虚拟 DOM （Vue/React）自动优化

## 渲染流水线

```
HTML → DOM → CSS → CSSOM → 合成 → 布局 → 绘制 → 显示
```

### 关键渲染路径
- 第一次把内容渲染到屏幕需要的资源和步骤
- 优化关键渲染路径可以加快首屏速度

## 浏览器缓存机制

见 HTTP 基础文档，浏览器缓存分：
- 强制缓存（Cache-Control / Expires）
- 协商缓存（Last-Modified / ETag）

## 同源策略 & 跨域

同源：协议 + 域名 + 端口 都相同才同源。

跨域解决方案：
- CORS（主流，后端配置响应头）
- JSONP（只支持 GET，老浏览器兼容）
- 代理开发（Vite/Webpack 配置代理）
- Nginx 反向代理
- postMessage 跨窗口通信

## 事件循环 Event Loop

JS 是单线程，异步任务通过事件循环执行。

### 宏任务 MacroTask
- `setTimeout` / `setInterval`
- `setImmediate`（Node.js）
- I/O 操作
- UI 渲染

### 微任务 MicroTask
- `Promise.then/catch/finally`
- `async/await` 实际基于 Promise
- `process.nextTick`（Node.js）
- `MutationObserver`

### 执行顺序
1. 执行同步代码，清空调用栈
2. 执行所有微任务
3. 执行宏任务队列中一个
4. 渲染UI
5. 重复，进入下一轮循环

**口诀**：同步先执行，微任务全清空，然后执行一个宏任务，然后渲染，循环。

## 垃圾回收 GC

### 标记清除 Mark-and-Sweep
- 从根对象（window）开始标记，能到达的就是存活，不能到达就是垃圾
- 清除标记的垃圾，现在浏览器都用这个

### 引用计数 Reference Counting
- 记录每个对象被引用次数，次数为 0 就回收
- 问题：循环引用无法回收，现在不用了

### 内存泄漏场景
- 全局变量未清理
- 定时器/setInterval 未清除
- 闭包持有引用
- 事件监听没移除
- DOM 删除了但引用还在

## V8 垃圾回收
- 分代回收：新生代 + 老年代
- 新生代：Scavenge 算法，空间小，回收快，复制清理
- 老年代：标记清除 + 标记整理，存活对象多

## 常见问题

### 为什么 CSS 放在 head，JS 放在 body 底部？
- CSS 放在 head 避免白屏，浏览器提前加载，不影响 HTML 解析
- JS 会阻塞 DOM 解析，放底部让页面先渲染出来，提升用户体验
- JS 如果要操作 DOM，需要等 DOM 加载完，放底部执行时机刚好

### 什么是防抖节流？
见 JavaScript 异步文档。

### localStorage vs sessionStorage vs cookie 区别
| | localStorage | sessionStorage | cookie |
|------|-------------|----------------|--------|
| 存储大小 | ~5MB | ~5MB | ~4KB |
| 过期时间 | 永久存在，除非手动删 | 关闭浏览器就清除 | 可设置过期时间 |
| 每次请求携带 | 不携带 | 不携带 | 自动携带到请求头 |
| 作用域 | 同源页面共享 | 当前标签页有效 | 同源共享 |

### 虚拟列表原理
只渲染可视区域内的元素，总高度用滚动条撑开，滚动时计算显示对应元素，解决大量数据渲染卡顿问题。
