# 微前端基础

## 什么是微前端
- 把一个大型前端应用拆分成多个独立的小型应用，每个可以独立开发、独立部署、独立运行
- 后端微服务的前端对应，适合大型项目多个团队协作开发

### 优点
- **技术栈无关**：每个子应用可以用不同框架（Vue/React/Angular都可以）
- **独立开发独立部署**：每个团队负责自己的，部署不影响别人
- **更快构建速度**：每个应用小，构建快
- **增量升级**：老项目慢慢拆，不用一次性全部重写
- **独立运行**：挂了一个不影响整体，容错更好

### 缺点
- **架构复杂**：要解决应用加载、样式隔离、JS隔离、通信这些问题
- **部署依赖**：需要主应用做基座调度
- **调试复杂度增加**：跨应用调试麻烦

## 常见微前端方案

### 1. iframe
最简单方案，每个子应用一个iframe，路由切换加载。

**优点**：简单，天然隔离，技术栈完全没关系
**缺点**：
- 地址栏变化不刷新，前进后退不好处理
- 全局状态不同步，弹窗这些高度不对
- 每次切换都重新加载，慢，用户体验差
- 全局样式（字体）不统一，js没法共享

现在很少用在主流程，只有部分嵌入场景用。

### 2. Single-SPA
最早的微前端框架，监听路由，根据路由加载对应子应用的生命周期。

- 不隔离样式和JS，需要自己处理
- 要修改子应用打包，输出生命周期函数
- 现在很多方案基于它改进

### 3. qiankun（乾坤，蚂蚁开源）
现在国内最流行，基于 Single-Spa 封装，解决了很多问题：
- **支持样式隔离**：默认开启，子应用样式不影响主应用和其他子应用
- **JS 沙箱隔离**：快照沙箱 / 代理沙箱，window 污染隔离
- **资源预加载**：预加载子应用，切换更快
- **支持多种引入方式**：HTML入口，配置注册，开箱即用
- **社区活跃，文档全**，很多公司在用

### 4. microApp（京东开源）
- 更轻量，基于 WebComponent + 虚拟路由
- 思路：把每个子应用包裹成自定义元素，通过 shadowDOM 隔离
- 接入零侵入，改很少代码就能用

### 5. Module Federation（Webpack 5 模块联邦）
Webpack 5 原生支持，共享模块，动态加载远程模块
- 原生支持，不用额外框架
- 更灵活，可以共享依赖
- 配置相对复杂一点

## qiankun 基本使用

### 主应用配置
```bash
npm install qiankun
```

```javascript
import { registerMicroApps, start } from 'qiankun';

registerMicroApps([
  {
    name: 'vueApp', // 子应用名字
    entry: '//localhost:8080', // 子应用地址
    container: '#container', // 挂载容器
    activeRule: '/app-vue', // 激活路由前缀
  },
  {
    name: 'reactApp',
    entry: '//localhost:8081',
    container: '#container',
    activeRule: '/app-react',
  },
]);

// 启动
start({
  sandbox: {
    strictStyleIsolation: true, // 严格样式隔离
    experimentalStyleIsolation: false,
  },
});
```

### 子应用配置 Vue 为例
1. `public-path.js`：
```javascript
if (window.__POWERED_BY_QIANKUN__) {
  __webpack_public_path__ = window.__INJECTED_PUBLIC_PATH_BY_QIANKUN__;
}
```

2. 入口文件 `main.js`：
```javascript
import './public-path';
import { createApp } from 'vue';
import App from './App.vue';

let app = null;
function render(props) {
  const { container } = props;
  app = createApp(App);
  app.mount(container ? container.querySelector('#app') : '#app');
}

// 独立运行直接渲染
if (!window.__POWERED_BY_QIANKUN__) {
  render({});
}

// 导出生命周期
export async function bootstrap() {
  console.log('vue app bootstrap');
}

export async function mount(props) {
  render(props);
}

export async function unmount() {
  app.unmount();
  app = null;
}
```

3. `vue.config.js` 配置：
```javascript
const { defineConfig } = require('@vue/cli-service');
module.exports = defineConfig({
  devServer: {
    port: 8080,
    headers: {
      'Access-Control-Allow-Origin': '*', // 允许跨域
    },
  },
  configureWebpack: {
    output: {
      library: `vueApp`,
      libraryTarget: 'umd', // 通用模块定义，qiankun能拿到
    },
  },
});
```

## 核心问题解决

### 1. 样式隔离
为什么需要：多个子应用样式互相污染，比如都有 `.btn` 类名。

方案：
- **Shadow DOM**：浏览器原生隔离，qiankun 和 microApp 都支持
- **CSS Module**：每个应用CSS模块化，类名编译后带hash
- **BEM 命名规范**：项目前缀，比如 `app1-*`，人工约定
- **CSS-in-JS**：JS写CSS，每个组件样式独立

qiankun 默认支持严格样式隔离，把样式放 Shadow DOM 里。

### 2. JS 沙箱隔离
为什么需要：子应用修改 window 全局变量会污染主应用和其他子应用。

方案：
- **快照沙箱**：激活子应用时保存window快照，卸载恢复快照，适合单实例
- **代理沙箱**：用 Proxy 代理 window，每个子应用一个代理，修改不影响全局，多实例支持
- **ifame 沙箱**：天然隔离，但是缺点多

qiankun 现在默认用代理沙箱。

### 3. 应用间通信
常见方式：
1. **基于 URL 参数**：跳转传参数，简单，适合跳转场景
2. **全局状态管理**：主应用提供一个共享 store，子应用订阅发布
3. **props 传递**：主应用在 mount 时候传给子应用 props，子应用传事件给主应用
4. **CustomEvent**：自定义事件，绑定在 window，不推荐，容易内存泄漏

qiankun 通信示例：
```javascript
// 主应用
registerMicroApps([
  {
    // ...
    props: {
      user: { name: 'zhangsan' },
      onLogin: handleLogin,
    },
  },
]);

// 子应用 mount
export async function mount(props) {
  console.log(props.user);
  props.onLogin();
}
```

### 4. 路由
两种方式：
- **主应用基于路由分发**：最常用，`/app1/*` 给 app1，`/app2/*` 给 app2
- **hash 路由每个子应用自己的前缀**：主应用解析hash前缀，对应到子应用

### 5. 资源共享
- **依赖共享**：主应用加载 react/vue，子应用不打进去，减小体积
- 模块联邦天生支持共享
- qiankun 也支持配置 externals

## 什么时候用微前端

**适合用：**
- 大型项目，多个团队开发
- 需要技术栈升级，又不能一次性重写老项目
- 不同产品线集成到一个平台

**不需要用：**
- 中小项目，本来就不大，没必要拆，增加复杂度
- 一个团队开发，拆分反而效率更低

**一句话：能用模块化解决就不用微前端，项目真的大到一定程度再考虑。**

## qiankun vs microApp 对比

| | qiankun | microApp |
|---|---------|----------|
| 作者 | 蚂蚁集团 | 京东零售 |
| 原理 | 基于 single-spa + 沙箱 | WebComponent + 虚拟路由 |
| 侵入性 | 需要改子应用入口 | 侵入性更小 |
| 功能完善度 | 功能完善，社区大 | 轻量，也够用 |
| 隔离性 | 沙箱+样式隔离 | ShadowDOM 天然隔离 |

## 总结
微前端是架构方案，适合大型项目多团队协作：
- 核心解决：独立开发部署，技术栈无关，增量升级
- 主流方案：qiankun 国内最流行，接入简单
- 核心问题：样式隔离、JS沙箱、应用通信
- 不要为了微前端而微前端，中小型项目别瞎折腾
