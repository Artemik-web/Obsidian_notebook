## 一、KPI设计原则

### 1.1 SMART原则
| 原则 | 说明 |
|------|------|
| **S** Specific | 指标具体，明确可描述，不能模糊 |
| **M** Measurable | 指标可量化，能够用数据衡量 |
| **A** Achievable | 目标可实现，跳一跳够得着，不切实际会反效果 |
| **R** Relevant | 与项目/公司目标相关，不设置无关指标 |
| **T** Time-bound | 有明确时间截止要求 |

### 1.2 二八原则
- 抓住20%的关键行为，完成80%的业绩
- 每个岗位KPI控制在 **5-8个** 以内，过多会分散注意力
- 区分关键指标和一般性工作

### 1.3 公平透明原则
- 指标提前公示，所有人清楚要求
- 数据来源公开可查，避免主观判断
- 同一岗位标准一致，不搞双重标准

## 二、KPI体系架构

```
公司/项目目标
    ├── 部门目标
    │   ├── 团队目标
    │   │   └── 个人KPI
    │   │   └── 个人KPI
    │   │   └── ...
    │   └── 团队目标
    │       └── ...
    └── 部门目标
        └── ...
```

### 2.1 目标分解流程
1. **确定公司/项目年度/季度总目标**
2. **部门承接**：部门分解到季度/月度
3. **团队承接**：团队分解到周期
4. **个人承接**：每个人明确自己的KPI

### 2.2 KPI权重分配
- 关键业绩指标：**60-70%**
- 能力成长指标：**15-25%**
- 价值观/协作指标：**10-15%**

> 权重示例：业绩 70% + 成长 20% + 协作 10% = 100%

## 四、评分标准

### 4.1 五级评分制

| 等级 | 分数范围 | 说明 | 分布比例建议 |
|------|----------|------|--------------|
| S | 90-100分 | 远超预期，贡献突出 | 10% |
| A | 80-89分 | 超出预期，表现优秀 | 20% |
| B | 70-79分 | 符合预期，完成工作 | 50% |
| C | 60-69分 | 低于预期，有待改进 | 15% |
| D | < 60分 | 不达标，需要整改 | 5% |

> 强制分布参考：S 10%, A 20%, B 50%, C 15%, D 5%
> 小团队可以不强制分布，但区分度要够

### 4.2 得分计算
```
个人总分 = Σ (指标得分 × 权重)
```

**示例：**
- 需求交付准时率：25分权重，目标90%，实际95% → 得分25 * (95/90) = 26.3 →  capped 25
- 代码质量：20分权重，实际0.3个/人月 < 0.5 → 得分20 → 总分继续累加

### 4.3 评级对应描述

| 等级 | 描述 |
|------|------|
| S | 持续超越岗位要求，主动解决重大问题，对团队有突出贡献 |
| A | 超出岗位要求，能够独立解决复杂问题，工作质量高 |
| B | 完全符合岗位要求，按质按量完成工作，满足期望 |
| C | 部分达不到岗位要求，需要督促，有待改进提升 |
| D | 达不到基本要求，工作经常出错，影响进度，需要调岗或淘汰 |

## 五、实施流程

### 5.1 周期设定
- **考核周期**：月度 + 季度 + 年度
- 月度：跟踪进度，快速反馈（不做总评级，只做跟踪）
- 季度：正式评级，应用激励
- 年度：综合评级，年终奖/晋升依据

### 5.2 实施步骤

```
周期开始
    ↓
1. 目标对齐会议：上级 + 个人 确认KPI指标和目标值
    ↓
2. 过程跟踪：每周站会同步进度，每月复盘偏差
    ↓
3. 周期结束：
    a. 个人自评：填写完成情况，数据支撑
    b. 上级评价：结合数据和表现给出评级
    c. 360度反馈（可选）：协作方评价（针对管理/协作岗）
    d. 沟通反馈：一对一面谈，明确优势和改进方向
    ↓
4. 结果应用：薪酬调整 / 奖金 / 晋升 / 培训
    ↓
下一周期开始
```

### 5.3 过程跟踪要点
- **数据化**：所有指标尽量用数据说话，减少主观判断
- **及时纠偏**：月度发现目标偏差，及时调整行动计划
- **不秋后算账**：过程中发现问题及时反馈，不要等到考核时再说

## 六、结果应用

### 6.1 薪酬奖金
| 评级 | 奖金系数 | 调薪幅度 |
|------|----------|----------|
| S | 1.5-2.0 | +10%-20% |
| A | 1.2-1.5 | +5%-10% |
| B | 1.0 | 0-5% |
| C | 0.5 | 不调薪 |
| D | 0 | 降薪或不涨 |

### 6.2 晋升发展
- 连续 **两个季度** S/A → 符合晋升候选条件
- 晋升评审时，KPI结果占 **60%** 权重
- S评级者优先获得更多发展机会、重点项目参与权

### 6.3 改进淘汰
- 一个季度 C → 发出警告，制定改进计划
- 一个季度 D 或 **连续两个季度** C → 触发：
  - 转岗安排
  - 解除劳动合同（按劳动法）

### 6.4 培训发展
- S/A级别：安排进阶培训、技术研讨、分享机会
- B级别：针对短板安排针对性培训
- C/D级别：安排基础技能培训，指定导师辅导

## 七、激励机制

### 7.1 物质激励
- **月度绩效奖金**：根据季度评级分档发放
- **项目奖金**：项目按时交付后额外奖励，按KPI贡献分配
- **年度奖金**：年终奖 × 个人KPI系数

### 7.2 精神激励
- **公示表扬**：季度S级员工在团队会上公开表扬
- **荣誉证书**：年度优秀员工颁发证书
- **署名权**：重要技术/产品方案贡献者署名

### 7.3 发展激励
- **优先参与**：新技术预研、重要项目优先分配给S/A员工
- **导师机会**：优秀员工可以带新人，积累管理经验
- **外部会议**：优先获得技术大会、行业会议参会资格

## 八、落地实现步骤

### 阶段一：准备阶段（1-2周）
- [ ] 确定公司/项目周期总目标
- [ ] 梳理各岗位岗位职责
- [ ] 制定各岗位KPI指标（参照本文第三章）
- [ ] 确定数据来源和统计方式
- [ ] 召开全员宣讲会，解释KPI制度

### 阶段二：试运行（1个季度）
- [ ] 各岗位确认第一季度KPI
- [ ] 按月度跟踪数据
- [ ] 季度结束后试运行评级
- [ ] 收集大家反馈，调整不合理指标
- [ ] 修改完善制度

### 阶段三：正式运行
- [ ] 按制度正常开展考核
- [ ] 每季度结束后：
  - [ ] 自评 → 上级评 → 沟通 → 结果应用
- [ ] 每年年底回顾，更新下一年指标

### 阶段四：持续优化（每年一次）
- [ ] 收集全年运行反馈
- [ ] 调整指标和权重
- [ ] 对齐新的年度目标
- [ ] 更新制度文档

## 九、常见问题与规避

### 9.1 常见误区

| 误区 | 问题 | 规避方法 |
|------|------|----------|
| 指标过多 | 每个人十几个指标，抓不住重点 | 控制在5-8个，突出关键 |
| 过度量化 | 所有东西都强制量化，反而失真 | 能量化量化，不能量化质化（360评价） |
| 目标太高 | 目标完全达不到，大家直接放弃 | 沟通确认，目标跳一跳够得着 |
| 目标太低 | 轻松完成，没有激励效果 | 对齐历史数据，设置合理挑战 |
| 只看结果不看过程 | 只看结果，忽略努力和客观变化 | 过程跟踪+结果评估结合 |
| 主观打分 | 老好人都打高分，无法区分 | 数据说话，强制分布，公示沟通 |
| KPI僵化 | 业务变化了指标不变 | 每季度可以微调，每年全面调整 |

### 9.2 特殊情况处理

**Q: 项目中途换了人，KPI怎么办？**
- A: 交接时重新确认KPI，按实际参与时间权重计算

**Q: 业务发生重大变化，原KPI不再适用怎么办？**
- A: 中期可以召开调整会议，重新协商KPI指标

**Q: 跨部门协作项目，指标怎么算？**
- A: 主要负责人占100%，参与人按贡献占比（比如30%）计入指标

**Q: 新人KPI怎么设置？**
- A: 第一个季度：学习成长指标权重调高到50%，业绩指标放低，以融入为主

## 总结

好的KPI制度不是为了扣分惩罚，而是：
1. **目标对齐** - 让所有人方向一致
2. **公平激励** - 让贡献大的人得到更多回报
3. **帮助成长** - 发现不足，持续改进
4. **淘汰惰性** - 淘汰不思进取的人，保持团队活力

> 定期回顾，持续优化，适合自己团队的才是最好的。
