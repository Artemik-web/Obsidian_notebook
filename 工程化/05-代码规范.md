# 代码规范与质量

## ESLint - 代码检查

ESLint 检查代码语法错误和风格问题。

### 配置 `.eslintrc.cjs`

```javascript
module.exports = {
  root: true,
  env: {
    browser: true,
    es2020: true,
    node: true,
  },
  extends: [
    'eslint:recommended',
    'plugin:@typescript-eslint/recommended',
    'plugin:react/recommended',
    'plugin:react/jsx-runtime',
    'prettier', // 和 prettier 冲突的规则关掉
  ],
  parser: '@typescript-eslint/parser',
  parserOptions: {
    ecmaVersion: 'latest',
    sourceType: 'module',
  },
  plugins: ['react-refresh'],
  rules: {
    'react-refresh/only-export-components': 'warn',
    'no-console': process.env.NODE_ENV === 'production' ? 'warn' : 'off',
    'no-debugger': process.env.NODE_ENV === 'production' ? 'error' : 'off',
  },
};
```

### 常用命令

```bash
# 检查所有文件
npx eslint .

# 自动修复能修的问题
npx eslint . --fix
```

### 在 VS Code 自动修复

设置保存自动修复：
```json
{
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": true
  }
}
```

## Prettier - 代码格式化

统一代码风格，所有人代码长一样。

### 配置 `.prettierrc`

```json
{
  "semi": true,
  "tabWidth": 2,
  "printWidth": 80,
  "singleQuote": true,
  "trailingComma": "es5",
  "endOfLine": "lf"
}
```

### 配置文件说明

| 配置 | 含义 |
|------|------|
| `semi: true` | 语句末尾加分号 |
| `singleQuote: true` | 用单引号不用双引号 |
| `tabWidth: 2` | 缩进 2 空格 |
| `printWidth: 80` | 一行最长 80 字符，超过换行 |
| `trailingComma: es5` | 对象数组最后一项也加逗号 |

### .prettierignore 忽略文件

```
node_modules
dist
*.md
```

## ESLint vs Prettier 分工

- **ESLint**：找语法错误，潜在 bug，代码质量问题
- **Prettier**：只管格式（缩进、引号、换行），不管对错

## Husky + lint-staged - Git 钩子

提交代码前自动检查，不合格不让提交。

### 安装配置

```bash
# 安装
npx husky install
npx husky add .husky/pre-commit "npx lint-staged"
```

`package.json` 添加配置：
```json
{
  "lint-staged": {
    "*.{js,jsx,ts,tsx}": [
      "eslint --fix",
      "prettier --write"
    ],
    "*.{json,md}": [
      "prettier --write"
    ]
  }
}
```

现在每次 `git commit`，只对暂存区的文件检查格式化，快！

## Commitlint - 提交信息规范

提交信息要符合格式，方便看变更历史。

### 格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

### type 类型

| 类型 | 含义 |
|------|------|
| `feat` | 新功能 |
| `fix` | 修复 bug |
| `docs` | 文档修改 |
| `style` | 格式改了，代码没变 |
| `refactor` | 重构，没加功能没修 bug |
| `perf` | 性能优化 |
| `test` | 测试相关 |
| `chore` | 构建/工具相关改动 |

### 例子

```
feat(login): 添加手机验证码登录

支持用户用手机号验证码登录，不用密码

Closes #123
```

### 配置

```javascript
// commitlint.config.js
module.exports = {
  extends: ['@commitlint/config-conventional'],
};
```

添加 commit-msg 钩子：
```bash
npx husky add .husky/commit-msg 'npx --no-install commitlint --edit "$1"'
```

## 为什么要做这些

### 好处
- 统一风格，每个人写出来代码风格一样，好读
- 提前发现错误，不用到线上才找到
- 提交信息清晰，看历史知道改了啥
- 代码审查更容易，减少无意义格式争论

### 团队开发必须
人多了，每个人习惯不一样，必须有规范约束。

## VS Code 设置推荐

```json
{
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.formatOnSave": true,
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": true
  }
}
```
