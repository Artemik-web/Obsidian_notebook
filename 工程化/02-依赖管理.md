# 依赖管理

## 包管理器对比

### npm
- Node.js 默认包管理器
- 嵌套 node_modules，可能重复依赖
- `package-lock.json` 锁版本

### yarn
- Facebook 出的，比 npm 快
- 并行安装，离线缓存
- `yarn.lock` 锁版本
- Workspace 原生支持 Monorepo

### pnpm
- **推荐现在用**
- 硬链接 + 符号链接，不重复存储相同版本
- node_modules 扁平化，幽灵依赖问题解决
- 速度比 npm/yarn 快
- `pnpm-lock.yaml` 锁版本
- 天生支持 Workspace/Monorepo

## SemVer 版本语义

版本格式：`主版本号.次版本号.修订号`

- **主版本号 (Major)**：不兼容的 API 修改，`1.x.x` → `2.0.0`
- **次版本号 (Minor)**：向下兼容的功能性新增，`1.1.x` → `1.2.0`
- **修订号 (Patch)**：向下兼容的问题修正，`1.1.0` → `1.1.1`

### 版本范围符号

| 符号 | 含义 | 例子 |
|------|------|------|
| `^` | 允许不修改主版本号的更新 | `^1.2.3` → `>=1.2.3 <2.0.0` |
| `~` | 允许不修改次版本号的更新 | `~1.2.3` → `>=1.2.3 <1.3.0` |
| `*` | 最新版本 | `*` → 任何版本 |
| `>` / `>=` / `<` / `<=` | 范围 | `>=1.0.0 <2.0.0` |
| 精确版本 | 完全匹配 | `1.2.3` → 就是 1.2.3 |

## 依赖分类

### dependencies (生产依赖)
项目运行必须的代码，打包进最终产物
```json
{
  "dependencies": {
    "react": "^18.0.0",
    "vue": "^3.0.0"
  }
}
```

### devDependencies (开发依赖)
开发构建过程需要用，项目运行不需要
```json
{
  "devDependencies": {
    "vite": "^5.0.0",
    "eslint": "^8.0.0",
    "typescript": "^5.0.0"
  }
}
```

## lock 文件作用

- 锁定依赖树的具体版本，保证每个人安装的都一样
- 即使语义版本范围允许更新，也使用经过测试的具体版本
- 不同包管理器 lock 文件不同，不能混用

| 包管理器 | lock 文件 |
|----------|-----------|
| npm | `package-lock.json` |
| yarn | `yarn.lock` |
| pnpm | `pnpm-lock.yaml` |

## 幽灵依赖问题

**什么是幽灵依赖**：代码能直接引用 `node_modules` 里你没写在 `package.json` 的依赖，因为扁平化把依赖提上来了。

pnpm 默认不扁平化，所以直接报错找不到，从根源解决问题。

## 依赖分析与优化

### 为什么要优化
- 依赖包太大，安装慢，打包慢
- 产物体积大，加载慢

### 常用命令
```bash
# npm 查看依赖树
npm ls

# npm 分析包大小
npm ls --all --json | grep name: | sort

# webpack-bundle-analyzer 分析打包体积
npx webpack-bundle-analyzer

# rollup 可视化
rollup --visualizer

# vite 插件：rollup-plugin-visualizer
```

### 优化方法
- 用更小的替代包：`lodash` → `lodash-es` 或者按需引入，或者用 `es-toolkit`
- 删除不用的依赖
- 避免全量引入，只按需引入
- 对大依赖用 CDN 外部引入，不打包

## 漏洞检测

```bash
# npm 内置检查
npm audit

# npm 自动修复
npm audit fix

# Snyk 专业检查
npx snyk test
```

# 单独作用域配置
@myorg:registry=http://registry.mycompany.com/
```

npm install -g nrm
nrm ls
nrm use taobao
```
