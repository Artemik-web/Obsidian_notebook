# 前端常用设计模式

设计模式是前人总结的可复用的代码设计经验，不用死记，理解常用场景会用就好。

## 设计模式三大分类

- **创建型**：对象创建相关，单例、工厂、原型
- **结构型**：类/对象组合，适配器、装饰器、代理
- **行为型**：对象之间交互，观察者、策略、命令、迭代器

## 常用设计模式

### 1. 单例模式 Singleton

**定义**：保证一个类只有一个实例，提供全局访问点。

**场景**：全局弹窗、全局状态管理、登录框、购物车、axios 请求实例。

**JS 实现**：
```javascript
class Singleton {
  constructor() {
    if (Singleton.instance) {
      return Singleton.instance;
    }
    Singleton.instance = this;
  }
}

// 闭包实现
const Singleton = (function() {
  let instance;
  return function() {
    if (!instance) {
      instance = this;
    }
    return instance;
  };
})();

// 实际项目中，用一个对象就可以当单例
const appStore = {
  state: {},
  getUser() {},
  setUser() {},
};
export default appStore;
```

### 2. 工厂模式 Factory

**定义**：定义一个创建对象的接口，让子类决定实例化哪个类。

**场景**：根据不同类型创建不同对象，统一管理创建逻辑。

**例子**：
```javascript
function createUser(type) {
  switch (type) {
    case 'admin':
      return { name: 'admin', permissions: 'all' };
    case 'user':
      return { name: 'user', permissions: 'read' };
    default:
      return { name: 'guest' };
  }
}

const user1 = createUser('admin');
```

### 3. 观察者模式 Observer / 发布订阅

**定义**：定义对象间一对多依赖，一个对象改变，通知所有依赖它的对象。

**场景**：事件总线、Vue 响应式、React 状态更新、DOM 事件。

**JS 简单实现**：
```javascript
class EventEmitter {
  constructor() {
    this.events = {};
  }

  on(eventName, callback) {
    if (!this.events[eventName]) {
      this.events[eventName] = [];
    }
    this.events[eventName].push(callback);
  }

  off(eventName, callback) {
    if (this.events[eventName]) {
      this.events[eventName] = this.events[eventName].filter(cb => cb !== callback);
    }
  }

  emit(eventName, ...args) {
    if (this.events[eventName]) {
      this.events[eventName].forEach(cb => cb(...args));
    }
  }
}

// 使用
const emitter = new EventEmitter();
const handle = data => console.log(data);
emitter.on('login', handle);
emitter.emit('login', { name: 'zhangsan' });
emitter.off('login', handle);
```

**Vue 响应式就是观察者模式**：数据变化 → 通知 Watcher → 更新组件。

### 4. 策略模式 Strategy

**定义**：定义一系列算法，把它们一个个封装起来，可以互相替换。

**场景**：表单验证不同规则、不同支付方式、不同平台分享。

**例子**：
```javascript
// 不同验证策略
const strategies = {
  required: (value) => !!value || '必填',
  email: (value) => /^\S+@\S+$/.test(value) || '邮箱格式不对',
  minLength: (value, len) => value.length >= len || `最少${len}个字符`,
};

// 验证器
class Validator {
  constructor() {
    this.rules = [];
  }

  add(value, strategy) {
    this.rules.push(() => strategy(value));
  }

  validate() {
    for (const rule of this.rules) {
      const result = rule();
      if (result !== true) {
        return result; // 返回错误信息
      }
    }
    return true;
  }
}

// 使用
const validator = new Validator();
validator.add('', strategies.required);
validator.add('abc', strategies.email);
console.log(validator.validate());
```

### 5. 代理模式 Proxy

**定义**：给对象提供一个代理，控制对这个对象的访问。

**场景**：缓存、防抖节流、懒加载、Vue3 响应式用了 Proxy。

**例子**：
```javascript
// 缓存代理，计算结果缓存
function cached(fn) {
  const cache = new Map();
  return new Proxy(fn, {
    apply(target, thisArg, args) {
      const key = JSON.stringify(args);
      if (cache.has(key)) {
        return cache.get(key);
      }
      const result = Reflect.apply(target, thisArg, args);
      cache.set(key, result);
      return result;
    },
  });
}

const expensiveCalc = cached((a, b) => {
  console.log('计算了');
  return a + b;
});

expensiveCalc(1, 2); // 计算了
expensiveCalc(1, 2); // 直接拿缓存
```

**Vue3 响应式就是用 Proxy 代理对象，get 时收集依赖，set 时触发更新**。

### 6. 装饰器模式 Decorator

**定义**：动态给对象添加额外功能，不改变原有结构。

**场景**：React 装饰器、扩展类方法、AOP 面向切面编程。

**例子**：
```javascript
// ES7 装饰器语法
function logClass(target) {
  console.log('创建类', target.name);
}

@logClass
class User {}

// 装饰方法
function readonly(target, key, descriptor) {
  descriptor.writable = false;
  return descriptor;
}

class Calculator {
  @readonly
  add(a, b) {
    return a + b;
  }
}
```

### 7. 适配器模式 Adapter

**定义**：将一个类接口转换成用户期望的另一个接口，让不兼容的接口可以一起工作。

**场景**：兼容老接口，适配第三方库。

**例子**：老接口返回数据格式不对，用适配器转成新格式：
```javascript
// 老接口返回 { user_name: '张三', user_age: 18 }
// 新接口要 { name: '张三', age: 18 }
function adapter(oldData) {
  return {
    name: oldData.user_name,
    age: oldData.user_age,
  };
}
```

### 8. 迭代器模式 Iterator

**定义**：提供一种方法遍历集合元素，不暴露内部表示。

**场景**：遍历不同结构的数据，统一接口。

JS 原生就有迭代器：
```javascript
const arr = [1, 2, 3];
const iterator = arr[Symbol.iterator]();
console.log(iterator.next()); // { value: 1, done: false }
console.log(iterator.next()); // { value: 2, done: false }

// 自定义迭代器
const myObject = {
  data: [1, 2, 3],
  [Symbol.iterator]() {
    let index = 0;
    return {
      next: () => {
        if (index < this.data.length) {
          return { value: this.data[index++], done: false };
        } else {
          return { done: true };
        }
      },
    };
  },
};
```

## 设计模式原则 SOLID

1. **单一职责**：一个类只做一件事
2. **开闭原则**：对扩展开放，对修改关闭
3. **里氏替换**：子类可以替换父类
4. **依赖倒置**：依赖抽象不依赖具体
5. **接口隔离**：多个小接口比一个大接口好

## 总结：什么时候用

| 模式 | 适用场景 |
|------|----------|
| 单例 | 全局唯一实例，弹窗、Store |
| 工厂 | 根据类型创建不同对象 |
| 观察者/发布订阅 | 事件通知，一对多依赖 |
| 策略 | 多个算法互换，验证、支付 |
| 代理 | 控制访问，缓存、拦截 |
| 装饰器 | 动态加功能，不修改原代码 |
| 适配器 | 接口兼容适配 |

前端常用就这些，不用学完 23 种设计模式，把这几个用熟就够了。
