# 移动端适配

## 视口 viewport

### 为什么需要 viewport
移动端屏幕比 PC 小，早期为了在小屏幕显示 PC 端网站，浏览器把页面缩放到视口里，用户缩放看。现在做移动端适配需要设置 viewport。

### viewport 设置
```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no">
```

参数：
- `width=device-width`：视口宽度等于设备宽度
- `initial-scale=1.0`：初始缩放 1 倍，不缩放
- `maximum-scale=1.0`：最大缩放 1 倍
- `user-scalable=no`：禁止用户缩放（一般不需要禁，可访问性不好）

## 适配方案

### 1. 流式布局（百分比布局）
- 宽度用百分比不用固定 px
- 配合 `min-width` `max-width` 限制范围
- 简单但大屏小屏比例不对，老网站用的多

```css
.container {
  width: 100%;
  max-width: 750px; /* 设计稿一般 750px */
  min-width: 320px;
}
```

### 2. flex 弹性布局
现在常用，弹性分配空间，兼容性好。

```css
.container {
  display: flex;
  justify-content: space-between;
}
.item {
  flex: 1;
}
```

### 3. rem 适配方案
**rem**：相对于根元素 `html` 的 `font-size` 单位。

原理：
- 根据屏幕宽度动态修改 html 的 font-size
- 所有尺寸用 rem 换算
- 屏幕大，font-size 大，整体等比例放大

实现：
```javascript
// 设计稿 750px，根节点 font-size = 屏幕宽度 / 7.5
function setRem() {
  const designWidth = 750; // 设计稿宽度
  const html = document.documentElement;
  const width = html.clientWidth;
  // 1rem = 100px 在设计稿上，方便换算：设计稿 px / 100 = rem
  html.style.fontSize = (width / designWidth) * 100 + 'px';
}
setRem();
window.addEventListener('resize', setRem);
```

css 写法：
```css
/* 设计稿 750px，元素宽度 100px → 1rem */
.box {
  width: 1rem; /* 对应设计稿 100px */
  height: 0.5rem; /* 对应设计稿 50px */
  font-size: 0.16rem; /* 16px */
}
```

优点：等比例适配所有屏幕，缺点：js 要动态计算。

现在用 postcss 插件 `postcss-pxtorem` 自动把 px 转成 rem，不用手动算。

### 4. vw/vh 方案（推荐现在用）
- `vw`：视口宽度的 1%，100vw = 整个视口宽
- `vh`：视口高度的 1%，100vh = 整个视口高
- `vmin`：取 vw vh 较小的那个，`vmax`：取较大的那个

换算：设计稿 750px → 100vw = 750px → 1px = 100vw / 750 ≈ 0.1333vw

所以设计稿上的 px 直接转 vw：
```css
/* 设计稿宽度 750px */
.box {
  width: (100 / 750 * 100vw); /* 100px → 13.3333vw */
}
```

用 `postcss-px-to-viewport` 插件可以自动转换，不用手动算。

**优点**：不用 js 动态计算，原生 CSS 单位，简单。兼容性：iOS 8+，Android 4.4+，现在基本都支持。

### 5. 媒体查询 Media Query
根据不同屏幕宽度设置不同样式：

```css
/* 小于 768px */
@media (max-width: 767px) {
  .container {
    width: 100%;
  }
}

/* 768px - 992px */
@media (min-width: 768px) and (max-width: 991px) {
  .container {
    width: 750px;
    margin: 0 auto;
  }
}
```

一般配合其他方案一起用，做特殊断点调整。

## 响应式设计
一套代码适配 PC 平板手机，不同屏幕显示不同布局。

要点：
- 流式布局 + 弹性图片 + 媒体查询
- 断点 breakpoints：一般常见断点
  - < 576px：手机
  - 576px ~ 768px：小屏平板
  - 768px ~ 992px：平板
  - 992px ~ 1200px：桌面
  - > 1200px：大屏桌面

框架 Bootstrap/Tailwind 都做好了响应式断点，直接用类就行。

## 高清屏 1px 问题
Retina 屏，CSS 里写 1px，实际显示 2 物理像素，看起来粗。

解决办法：
```css
.border-1px {
  position: relative;
}
.border-1px::after {
  content: '';
  position: absolute;
  left: 0;
  bottom: 0;
  width: 100%;
  height: 1px;
  background: #000;
  transform: scaleY(0.5);
  transform-origin: bottom;
}
```

原理：CSS 1px 缩放到 0.5，对应物理像素 1px。

## 移动端常见问题

### 为什么 `viewport-fit=cover`
iPhone X 及以后有刘海屏，内容会被刘海挡住，需要设置：
```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover">
```
css 用 `safe-area-inset-left` 等处理：
```css
body {
  padding-left: env(safe-area-inset-left);
  padding-right: env(safe-area-inset-right);
}
```

### 点击穿透问题
移动端点击浮层，浮层消失后，底层点击也触发了。

解决：
- 浮层消失后 `e.preventDefault()`
- 或者用 touchend 代替 click，延迟 300ms 消失，或者直接阻止默认行为

### 300ms 点击延迟
老版 iOS Safari，双击缩放，所以点击后等 300ms 看是不是双击。

解决：
```html
<meta name="viewport" content="user-scalable=no">
```
或者用 `fastclick` 库，现在新浏览器都修复了，基本不用处理了。

### 禁止长按选中文本
```css
.user-select-none {
  -webkit-user-select: none;
  user-select: none;
}
```

## 适配方案总结

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| 百分比 | 简单 | 比例不好控制 | 老项目 |
| rem | 等比例适配 | 需要JS | 移动端H5 |
| vw | 原生不需要JS | 低版本不支持 | **现在推荐** |
| 响应式 | 一套适配多端 | 布局复杂 | 兼容PC+移动 |

**现在新项目推荐：vw + flex + 媒体查询**，简单够用。
